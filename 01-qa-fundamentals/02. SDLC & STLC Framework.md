# 🔄 SDLC & STLC Framework

> เข้าใจวงจรการพัฒนา Software (SDLC) และกระบวนการทดสอบ (STLC) เพื่อให้เห็นภาพว่า QA ทำงานร่วมกับทีมตั้งแต่ Requirement จนถึง Release อย่างไร

---

# 🏗️ SDLC (Software Development Life Cycle)

SDLC คือกระบวนการสร้าง Software ตั้งแต่เริ่มต้นวิเคราะห์ความต้องการ จนถึงการใช้งานจริงและ Maintenance

## เป้าหมาย

- สร้าง Software ที่ตอบโจทย์ผู้ใช้และธุรกิจ
- ส่งมอบระบบที่มีคุณภาพตามเวลาและงบประมาณ

## ขั้นตอนหลัก

1. Requirement Analysis
   - วิเคราะห์ความต้องการ
   - ระบุ Business Requirement

2. Design
   - ออกแบบระบบ
   - ออกแบบ UI/UX

3. Development
   - Developer พัฒนา Software

4. Testing
   - ตรวจสอบว่า Software ทำงานตาม Requirement
   - ค้นหา Defect และความเสี่ยง
   - Verify ผลลัพธ์ก่อน Release

5. Deployment
   - Release ระบบให้ผู้ใช้

6. Maintenance
   - แก้ไขปัญหา
   - ปรับปรุงระบบ


---

# 👤 QA Role in SDLC

| Phase | QA Responsibility |
|---|---|
| Requirement | Review Requirement, Find Gap |
| Design | ตรวจสอบ Testability |
| Development | เตรียม Test Approach และ Test Data |
| Testing | Execute Test, Report Defect, Verify Fix |
| Deployment | สนับสนุน Release Decision |
| Maintenance | Regression และตรวจสอบ Bug Fix |


---

# 🧪 STLC (Software Testing Life Cycle)

STLC คือกระบวนการทำงานของ QA เพื่อวางแผน ออกแบบ ทดสอบ และสรุปผลการทดสอบ


| Step                                    | Purpose                         | Output                 |
| --------------------------------------- | ------------------------------- | ---------------------- |
| Requirement Analysis                    | วิเคราะห์ Requirement และหา Gap | Testable Requirement   |
| Test Planning                           | กำหนด Scope, Strategy, Risk     | Test Plan              |
| Test Design                             | สร้าง Test Case และ Test Data   | Test Cases             |
| Test Implementation / Environment Setup | เตรียมระบบและข้อมูลทดสอบ        | Ready Environment      |
| Test Execution                          | ทดสอบและแจ้ง Defect             | Test Results + Defects |
| Test Closure                            | สรุปผลและ Lesson Learned        | Test Summary Report    |

# 🔄 SDLC & STLC in Agile

ใน Agile กระบวนการเหล่านี้ไม่ได้ทำครั้งเดียวแบบ Waterfall

แต่จะเกิดซ้ำในแต่ละ Sprint

ตัวอย่าง:

Sprint:
- Requirement Discussion
- Development
- Testing
- Review
- Retrospective


QA จึงต้องเข้าร่วมตั้งแต่ต้น Sprint ไม่ใช่รอ Testing Phase

---

# 💡 Key Takeaways

- SDLC คือกระบวนการสร้าง Software
- STLC คือกระบวนการทำงานด้าน Testing
- QA ไม่ได้ทำงานเฉพาะตอน Testing
- QA มีบทบาทตั้งแต่ Requirement
- การเข้าใจ SDLC/STLC ช่วยให้ QA ทำงานร่วมกับทีมได้ดีขึ้น
