# 🧪 06. Testing Types Overview

> ประเภทของการทดสอบซอฟต์แวร์ที่ QA ใช้เพื่อประเมินคุณภาพ ความถูกต้อง และความเสี่ยงของระบบ

**Purpose:**

เข้าใจรูปแบบการทดสอบหลัก ๆ และเลือกวิธี Testing ให้เหมาะสมกับเป้าหมาย ความเสี่ยง และบริบทของระบบ

---

## 🎯 1. Functional Testing

เป็นการทดสอบว่าระบบทำงานตาม Requirement และ Business Requirement ที่กำหนดไว้หรือไม่

QA จะตรวจสอบว่า Feature ต่าง ๆ ทำงานถูกต้องตามที่คาดหวัง

**Example: Login**

QA ตรวจสอบว่า:

- ผู้ใช้กรอก Username / Password ถูกต้องแล้วสามารถเข้าสู่ระบบได้
- กรอกข้อมูลผิดต้องแสดง Error Message ที่เหมาะสม
- ระบบไม่อนุญาตให้ Login เมื่อข้อมูลไม่ถูกต้อง

---

## ⚙️ 2. Non-Functional Testing

เป็นการทดสอบคุณภาพด้านอื่น ๆ นอกเหนือจากการทำงานของ Feature

เน้นตรวจสอบว่า "ระบบทำงานได้ดีแค่ไหน"

ตัวอย่าง:

### Performance Testing

ตรวจสอบ:

- ความเร็วในการตอบสนอง
- ความสามารถในการรองรับจำนวนผู้ใช้

### Usability Testing

ตรวจสอบ:

- ความง่ายในการใช้งาน
- User Experience

### Security Testing

ตรวจสอบ:

- ช่องโหว่
- การป้องกันข้อมูล

### Reliability Testing

ตรวจสอบ:

- ความเสถียรของระบบ
- การทำงานต่อเนื่อง

### Compatibility Testing

ตรวจสอบ:

- Browser
- Device
- Operating System

---

# 🏗️ 3. Test Levels

การทดสอบสามารถแบ่งตามระดับของระบบได้

## Unit Testing

ทดสอบส่วนเล็กที่สุดของระบบ เช่น Function หรือ Component

โดยทั่วไป Developer เป็นผู้ทำ

---

## Integration Testing

ทดสอบการทำงานร่วมกันระหว่าง Module หรือ Service

**Example:**

- Frontend ติดต่อ Backend
- Payment Service ติดต่อระบบภายนอก

---

## System Testing

ทดสอบระบบทั้งหมดในมุมมองของผู้ใช้งาน

ตรวจสอบว่า Feature ต่าง ๆ ทำงานร่วมกันได้ถูกต้อง

---

## Acceptance Testing (UAT)

ทดสอบเพื่อยืนยันว่าระบบตอบโจทย์ความต้องการของ Business และ User จริง

มักเกี่ยวข้องกับ:

- Customer
- Business Owner
- Stakeholder

---

## ♻️ 4. Regression Testing

หลังจากมีการแก้ไข Code หรือเพิ่ม Feature ใหม่ QA ต้องทดสอบส่วนที่เคยทำงานได้แล้วอีกครั้ง

จุดประสงค์:

- ตรวจสอบว่า Feature เดิมยังทำงานได้
- ป้องกัน Bug ใหม่จากการเปลี่ยนแปลง

**Example:**

แก้ระบบ Payment

QA ต้องตรวจสอบ:

- Checkout
- Order History
- Receipt

---

## 🚦 5. Smoke Testing

เป็นการทดสอบแบบรวดเร็ว เพื่อยืนยันว่า Build หรือระบบหลักสามารถใช้งานได้

ใช้ตรวจสอบก่อนเข้าสู่ Testing ขั้นละเอียด

**Example:**

ระบบ E-commerce:

- เปิดเว็บไซต์ได้
- Login ได้
- เพิ่มสินค้าได้
- Checkout ได้

ถ้า Core Function ใช้งานไม่ได้ อาจหยุด Testing และส่งกลับให้ Development แก้ไข

---

## 🔎 6. Sanity Testing

เป็นการทดสอบเฉพาะส่วนที่มีการเปลี่ยนแปลงหรือแก้ไข

ใช้เพื่อยืนยันว่า Bug ที่แก้ไข หรือ Feature ใหม่ ทำงานถูกต้อง

**Example:**

แก้ไขปัญหา Login

QA ตรวจสอบเฉพาะ:

- Login Success
- Login Failure
- Error Message

---

## 🧪 7. Exploratory Testing

เป็นการทดสอบแบบยืดหยุ่น โดย QA ใช้ความรู้ ความเข้าใจ และประสบการณ์ในการค้นหา Defect

ไม่ได้ยึดตาม Test Case อย่างเดียว

QA จะ:

- เรียนรู้ระบบ
- ตั้งคำถาม
- ทดลอง Scenario ที่อาจเกิดปัญหา

เหมาะกับ:

- ระบบใหม่
- Feature ที่ซับซ้อน
- การค้นหา Bug ที่คาดไม่ถึง

---

## 🤖 8. Automation Testing

เป็นการใช้ Script หรือ Testing Tool เพื่อช่วยทดสอบระบบอัตโนมัติ

เหมาะกับ:

- Regression Testing
- Repeated Testing
- Test ที่ต้องรันบ่อย

**Example:**

ใช้ Playwright ตรวจสอบ Login Flow อัตโนมัติทุกครั้งที่มีการเปลี่ยนแปลงระบบ

---

# 🧠 Why this matters

ประเภทการทดสอบแต่ละแบบช่วยให้ QA มองความเสี่ยงจากมุมที่แตกต่างกัน

QA ไม่ควรเลือกวิธี Testing แบบเดียวกับทุกระบบ แต่ควรเลือกให้เหมาะกับ:

- ประเภทของ Product
- ความเสี่ยง
- Business Impact
- เป้าหมายของการทดสอบ

QA ที่ดีต้องเข้าใจว่า:

> "ควรใช้การทดสอบแบบไหน กับปัญหาแบบไหน"

---

# 💡 Key Takeaways

- Functional Testing ตรวจสอบว่าระบบทำงานถูกต้องหรือไม่
- Non-Functional Testing ตรวจสอบคุณภาพด้านอื่นของระบบ
- Test Levels ช่วยให้เข้าใจว่าควรทดสอบในระดับไหน
- Regression Testing ช่วยป้องกันผลกระทบจากการเปลี่ยนแปลง
- Smoke Testing ตรวจสอบระบบหลักอย่างรวดเร็ว
- Sanity Testing ตรวจสอบเฉพาะส่วนที่แก้ไข
- Exploratory Testing ช่วยค้นหา Defect ที่อาจไม่อยู่ใน Test Case
- Automation Testing ช่วยลดงานซ้ำและเพิ่มความเร็วในการทดสอบ
