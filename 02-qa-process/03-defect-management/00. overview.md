> **Now that you have Test Cases → How to Execute and Report Defects?**

## 🎯 Workflow: Execute Tests → Find Defects → Report & Track

```
┌─────────────────────────────────────────────────────────────────┐
│ INPUT: Approved Test Cases + Test Data                          │
│ (จาก 02-test-design-data)                                       │
└──────────────────────────┬──────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│ STEP 1: UNDERSTAND BUG MANAGEMENT PROCESS                       │
│ ├─ ไฟล์: 01. Bug Management Overview.md                          │

├─────────────────────────────────────────────────────────────────┤

├─────────────────────────────────────────────────────────────────┤
│ STEP 4: VALIDATE BUG REPRODUCIBILITY                            │
│ ├─ ไฟล์: 04. Bug Reproducibility & Environment Awareness.md      │

│ STEP 6: TRACK DEFECT LIFE CYCLE                                 │
│ ├─ ไฟล์: 06. Defect Life Cycle.md                                │
│ ├─ ทำอะไร: ติดตาม Bug: New → Assigned → Fixed → Closed            │
│ └─ Output: Bug Status Updates                                   │

│ STEP 7: BUG TRIAGE MEETING                                      │
│ ├─ ไฟล์: 07. Bug Triage Meeting.md                               │

│ └─ Output: Prioritized Bug List                                 │
├─────────────────────────────────────────────────────────────────┤
│ STEP 8: IDENTIFY ROOT CAUSES                                    │
│ ├─ ไฟล์: 08. RCA (Root Cause Analysis).md                        │
│ ├─ ทำอะไร: ถ้า Bug ตัวสำคัญ → จัดการหา Root Cause                    │
│ └─ Output: RCA Document (ทำไม bug เกิด + วิธีป้องกัน)                 │
├─────────────────────────────────────────────────────────────────┤
│ FINAL OUTPUT: Quality Metrics                                   │
│ ├─ ✅ Total Test Cases Executed                                 │
│ ├─ ✅ Total Defects Found (by Severity)                         │
│ ├─ ✅ Defect Closure Rate                                       │
│ ├─ ✅ Quality Insights (RCA)                                    │
│ └─ ✅ Ready for Test Reporting (04-test-reporting)              │

              พร้อมสำหรับ STEP ถัดไป:
         04-Test-Reporting (Summarize Results)
```

## 📚 แต่ละไฟล์อธิบายว่า

### 1️⃣ [01. Bug Management Overview](01.%20Bug%20Management%20Overview.md)
**ทำไมต้อง?** มีระเบียบในการจัดการ Bug เพื่อไม่ให้บั๊ก Slip ผ่าน Release หรือ Bug ซ้ำเกิด

**เช็คอะไร?**
- ✅ Bug workflow คือ: Report → Triage → Assign → Fixed → Verify → Closed
- ✅ ใครทำอะไรในแต่ละ Stage?
- ✅ Bug tracking tool ใช้อะไร?

**Output:**
- Clear Bug Management Process

---

### 2️⃣ [02. Anatomy of Bug Report](02.%20Anatomy%20of%20Bug%20Report.md) + [03. Bug Report](03.%20Bug%20Report.md)
**ทำไมต้อง?** Bug Report ต้องเขียนให้ Dev เข้าใจได้ทันที (ไม่ต้องถามกลับ BUG ไนต้ห)

**เช็คอะไร?**
- ✅ Bug ID Unique ไหม?
- ✅ Title ชัดไหม? (คนอื่นรู้ Bug นี้ได้โลย)
- ✅ Severity ถูกไหม? (Hit May vs. Annoyance)
- ✅ Steps to Reproduce ชัดไหม? (Dev รันได้หรือ)
- ✅ Actual vs. Expected Result ชัดไหม?
- ✅ Environment / Browser / Device / OS รายงานไหม?
- ✅ Attachment (Screenshot / Log) พอไหม?

**Output:**
- Clear, Actionable Bug Reports

---

### 3️⃣ [04. Bug Reproducibility & Environment Awareness](04.%20Bug%20Reproducibility%20%26%20Environment%20Awareness.md)
**ทำไมต้อง?** Bug สามารถ Reproduce ได้ = Bug จริง; Bug ไม่ Reproduce แล้ว = อาจเป็น Environment issue หรือ Bug ถูกแก้

**เช็คอะไร?**
- ✅ Bug Reproducible ไหม? (Consistent หรือ Intermittent)
- ✅ Bug เป็นปัญหา Environment หรือ Code?
- ✅ Browser / Device / OS ที่ Bug เกิดบ้าง?
- ✅ Network Environment ส่งผลไหม?

**Output:**
- Bug Status: Confirmed / Cannot Reproduce / Environment Issue

---

### 4️⃣ [05. Severity vs Priority](05.%20Severity%20vs%20Priority.md)
**ทำไมต้อง?** ต้องบอก Dev ว่า Bug นี้ "เสียหาย" แค่ไหน (Severity) กับ "ต้องแก้" เดี๋ยวนี้หรือ (Priority)

**เช็คอะไร?**
- ✅ **Severity** (Impact ต่อ Function):
  - **Critical:** ระบบพังหลวง / Data Loss / Security issue
  - **High:** Feature ไม่ทำงาน แต่ระบบยังไป
  - **Medium:** Feature ทำงาน แต่ผิด Logic
  - **Low:** UI Minor / Typo
- ✅ **Priority** (ต้องแก้เดี๋ยวนี้ไหม):
  - **P1:** ต้องแก้ไว ASAP (อาจจะก่อน Release)
  - **P2:** ต้องแก้ใน Sprint นี้
  - **P3:** ต้องแก้ แต่ไม่รีบ
  - **P4:** ต่อไปแก้หรือให้ยา 🙂

**Output:**
- Bug Severity & Priority Matrix

---

### 5️⃣ [06. Defect Life Cycle](06.%20Defect%20Life%20Cycle.md)
**ทำไมต้อง?** ติดตาม Bug ตั้งแต่พบ ลงไปจนกว่าแก้ปิด (ไม่ให้หายสายลับ)

**Bug Workflow:**

```
NEW → ASSIGNED → IN PROGRESS → FIXED → RETEST → CLOSED
       (Dev)    (Dev)        (Dev)    (QA)     (QA)
```

**Output:**
- Bug Status Tracking

---

### 6️⃣ [07. Bug Triage Meeting](07.%20Bug%20Triage%20Meeting.md)
**ทำไมต้อง?** Bug เยอะไป ทีมต้องประชุมตัดสินใจว่า Bug ไหน ต้องแก้ก่อน-หลัง หรือให้ยา

**เช็คอะไร?**
- ✅ ประชุมผู้เข้า: QA Lead, Dev Lead, PM, ผู้บริหาร
- ✅ ตัดสินใจให้ Bug ไหน: Fix / Defer / Reject
- ✅ Re-prioritize Bug ตามความจำเป็น

**Output:**
- Prioritized Bug List สำหรับ Dev Sprint

---

### 7️⃣ [08. RCA (Root Cause Analysis)](08.%20RCA%20(Root%20Cause%20Analysis).md)
**ทำไมต้อง?** เมื่อ Bug สำคัญ ต้องเข้าไปดูว่า "ทำไม" bug เกิด (เช่น Code Review ไม่จัด? Test ไม่กว้าง? Requirement ไม่ชัด?)

**เช็คอะไร?**
- ✅ Root Cause คืออะไร (Code / Process / Requirement)?
- ✅ วิธีป้องกัน Bug แบบเดียวกันนี้ในอนาคต?

**Output:**
- RCA Report (ป้องกัน Bug ซ้ำเกิด)

## 🎬 Example Workflow

### 📥 Input: Test Execution

> ทำการทดสอบ 3 Test Cases (TC001, TC002, TC003)

---

### ⚙️ Step 1: Execute & Result

| TC ID | Status | Remark |
|---|---|---|
| TC001 | **PASS** | Withdraw Success ✅ |
| TC002 | **FAIL** ⚠️ | Balance should = 0, but = 500 |
| TC003 | **PASS** | Error Message ✅ |

---

### ⚙️ Step 2: Write Bug Report (TC002 Fail)

**Bug Report:**

```
BUG ID: BUG-001
Title: Balance not updated after withdrawal
Severity: HIGH (Data Loss potential)
Priority: P1 (Must fix before Release)

Environment: Chrome 120, Windows 10
Steps to Reproduce:
  1. Login as User_Boundary (Balance = 500)
  2. Withdraw 500 (Amount = Balance)
  3. Click Confirm

Expected: Balance = 0
Actual: Balance = 500 (Balance not deducted!)

Attachment: [Screenshot showing Balance still 500]
```

---

### ⚙️ Step 3: Validate Reproducibility

**ลองอีกครั้ง:**
- ✅ Reproduce ได้ (Consistent)
- ✅ ไม่ใช่ Network issue
- ✅ Bug Confirmed

**Status:** Confirmed Bug

---

### ⚙️ Step 4: Severity & Priority

- **Severity:** HIGH (Data Loss - Balance not updated)
- **Priority:** P1 (Must fix before Release - impacts critical feature)

---

### ⚙️ Step 5: Lifecycle

```
NEW → ASSIGNED (to Dev) → IN PROGRESS → FIXED → RETEST (QA) → CLOSED
```

---

### ⚙️ Step 6: Triage Meeting

```
QA Lead:     "Bug BUG-001 is HIGH/P1 - Balance not updating"
Dev Lead:    "We'll fix in this Sprint"
PM:          "OK, must release clean"
Decision:    FIX (before Release)
```

---

### ⚙️ Step 7: RCA (if Critical)

**Root Cause:**
- Dev forgot to call `updateBalance()` API after withdrawal

**Prevention:**
- ✅ Code review checklist ต้อง include "API calls"
- ✅ Unit test coverage ต้องครอบ Balance update

---

### 📤 Final Output: Quality Metrics

✅ Tests Executed: 3 TC  
✅ Passed: 2 TC  
✅ Failed: 1 TC  
✅ Defects Found: 1 (BUG-001)  
✅ Defect Severity: HIGH  
✅ Defect Status: Confirmed → Fixed → Ready for Retest  
✅ RCA: Root Cause Identified + Prevention in Place  

**→ พร้อมสำหรับ STEP ถัดไป: 04-Test-Reporting (Generate Test Summary)**

## 📖 How to Use This Section

1️⃣ **เข้าใจกระบวนการ:** เปิด 01. Bug Management Overview → เข้าใจ Workflow  
2️⃣ **รัน Test Cases:** Execute Tests ตามแผน  
3️⃣ **ถ้า Test Fail:** เปิด 02-03. Bug Report → เขียน Bug อยู่าละเอียด  
4️⃣ **Validate Bug:** เปิด 04. Bug Reproducibility → เช็คว่า Bug จริง  
5️⃣ **Assign Severity/Priority:** เปิด 05. Severity vs Priority → ระบุระดับ  
6️⃣ **Track Bug:** เปิด 06. Defect Life Cycle → ติดตาม Bug  
7️⃣ **Triage Meeting:** เปิด 07. Bug Triage Meeting → ประชุมตัดสินใจ  
8️⃣ **RCA:** เปิด 08. RCA → ถ้า Bug สำคัญ → หา Root Cause  
9️⃣ **สรุปผล:** ไปแล้ว 09. Summary → เตรียม Report ต่อไป  

---

## 💡 Key Principle

> **Bug Report ที่ดี = Dev เข้าใจทันที + ไม่ต้อง Clarification**

ส่วนนี้คือการเรียนรู้ว่า "ทำให้ Bug ตายเร็ว" ไม่ใช่ให้ Bug ลอยไป ปัดปลายอื่น
